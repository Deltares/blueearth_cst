# Repository layout

Last updated: 2026-11-03

`AGENTS.md` § Repo Map carries the summary. This file covers the rest of the tree.

## blueearth_cst/

Modules invoked from Snakemake `script:` directives (Python) or `Rscript --vanilla` `shell:` bodies (R). None is a standalone CLI.

Split by stage — `model/`, `projections/`, `climate_analysis/`, `experiment/` — plus `weathergen/` for the R weather generator and `shared/` for cross-cutting helpers:

| Helper | Holds |
|---|---|
| `snake_utils.py` | config parsing for every Snakefile |
| `run_logged.py` | logged subprocess execution |
| `climate_parity.py` | the engine-neutral regrid/PET transform |
| `cross_workflow_leaves.py` | the wf1 outputs WF3 declares but cannot build |
| `spatial_geoms_parity.py` | which of the two geoms trees answers which question |
| `interchange_contracts.py` | the wf1 → wf2/wf3 seam |

## config/

Five bins plus `advanced_settings.yml`.

**No `workflows/` bin.** Every shipped `--configfile` target sits beside the project it writes into, under `test_case/`, which is how a real project is laid out.

**`defaults/` vs `templates/`.** `defaults/` is read by rules, so changing one changes a run (`wflow_build_model.yml`, `wflow_update_waterbodies.yml`, `weathergen_config.yml`). `templates/` is only scaffolds you copy. Each has its own README.

`<project_dir>/config/templates/` is a different thing — a generated snapshot bin, normally empty. A file lands there only when a project points a key at its own copy; a shipped default is recorded by git blob id instead. The tracked `wflow_sbm.reference.toml` is reference only: nothing reads it, and it lags what a build emits.

**`indicator_sets/`** holds the bundled WF4 indicator sets (`default.yml`), resolved by set id against the installed repository, never the working directory. Changing one changes which indicators a run publishes; custom sets live beside their project and are copied from `templates/indicator_set.template.yml`.

**`catalogs/`** holds the hydromt `-d` targets. `cmip6_data.yml` and `cmip6_store_index.json` are generated by `dev/scripts/generate_cmip6_catalog.py` from a live `gs://cmip6` listing — never hand-edit them. Both carry a `crawled_on` from the same crawl, and a consumer asserts the two are equal.

**`basemap/`** holds `natural_earth_50m.gpkg`, the only geographic data committed here, used for the basin map's locator inset. It is vendored because `cartopy.feature.COASTLINE` fetches Natural Earth on first use and caches it per user, so two machines can disagree. Treat it as a static cartographic asset, not a precedent for committing basin data. Provenance, licence and rebuild recipe: `config/basemap/README.md`.

**`advanced_settings.yml`** carries `constraints:` (hard limits no project config may relax, e.g. `min_historical_years`), `defaults:` (starting values a project may override, e.g. `julia_threads`), and `runtime:` (toolchain pins, e.g. `julia_version`, which `pixi.toml` and `Manifest.toml` must match — `tests/test_julia_runtime.py` enforces it). It is not a `--configfile` target; `snake_utils` reads it once for every project. Its schema is closed, so add a setting to the file and to `_ADVANCED_SETTINGS_SCHEMA` in `blueearth_cst/shared/advanced_settings.py` together (kept out of `wf3_science.py` so a schema edit cannot re-key WF3 scenario collections).

**Tracked files under `test_case/`** are only `project_config_*.yml` and the two basin-input CSVs under `test_data/`. Keep the `project_config_` prefix on any new seed config: a name outside that glob is silently untracked. Un-ignoring needs the pattern form (`test_case/*`), not the directory form, because git will not un-ignore a file whose parent directory is excluded — which is also why the CSVs take three lines: un-ignore the directory, re-exclude its contents, re-include `*.csv`.

## scripts/

User-facing runners, indexed in `scripts/README.md`.

`suggest_experiment_name.py` previews selection without editing YAML or reserving a directory.

The simulation's `experiment_name` is optional. Unset, runners start at `stress_test_01`; plain reruns
select the highest allocation regardless of completion. Only `--new-experiment` advances numbering.
A custom base selects its own family; an exact numbered name pins it. Existing owned dated or unnumbered
experiments remain explicit legacy selections. The resolver lives in `experiment/reservation.py`.

Historical implementation and landing evidence: implementation-evidence.md (private-checkout-only citation:
`../records/validation/experiment-numbering-2026-10-10/implementation-evidence.md`).

## tests/

Shared tests stay at their existing paths. `tests/private/` groups tests of personal activation,
task/board coordination, sealed private records and repository synchronization; these files are
excluded from the public projection. `pytest tests/` discovers both groups in a private checkout.
Moving a test into this directory also requires updating its repository-root calculation and the
export policy; the current engine does not infer visibility from directory names.

`tests/data/gev-lmoments/` owns the public frozen GEV parity controls. Its README records their
provenance; original historical evidence stays unchanged in private `dev/records/`. Public tests
must consume the shared fixtures, without depending on private history being present.

## dev/

Planning, audits, design docs, conventions, roadmap, the baseline manifest, and helpers under `dev/scripts/`. Not shipped.

`dev/scripts/private/` groups personal activation, task/board coordination, navigation and repository
synchronization helpers. The entire directory is omitted from the public projection. Shared developer
helpers remain directly under `dev/scripts/`; do not move one solely because it is development tooling.

`dev/reference/private/` holds private activation and task/session coordination guidance. Shared
development and toolbox references stay directly under `dev/reference/`; the reference index identifies
private-checkout-only citations. Both private directories are omitted as directory prefixes.

`scaffold_project_tree.py` supports static WF0–2 layouts only. It refuses WF3/4,
whose output identities require executed checkpoints; inspect a completed run
with `snapshot_project_tree.py --config <config> --project-dir <root>` instead.

The development workflow (private-checkout-only citation:
`private/dev-task-and-session-workflow.md#task-admission-and-the-board`) owns board location, task admission,
rendering, and coordination. The [record lifecycle](dev-record-lifecycle.md) owns promotion and retention.
`dev/README.md` is the folder map and contributor entry point.

Use `dev/reference/README.md` to find the existing topic owner for current rules and architecture.
Reusable report/review artifacts and their usage guides live in `dev/templates/`.
Snapshot diagrams and render previews belong in task scratch. Retain one under records only when it
provides evidence needed beyond the task; the record lifecycle governs retention.
Keep proposals with tasks and dated evidence under records; neither supplies current compliance rules.

The wrapper gives Item and Area / Origin up to 110 and 44 characters. The `#`
column comes from each todo note's `queue`: lower numbers come first, with newer
IDs first within a shared rank. Rank correctness risks and work that unblocks
others ahead of routine improvements; use progress to break comparable cases,
and defer blocked or run-dependent work when its prerequisite is unavailable.
Someday and closed records are excluded from Work and available through explicit views. Priority edits
belong in the notes and require a render; they do not change lifecycle status or compact other ranks.

Pre-board item IDs cited by code, tests and Snakefiles are recoverable from
commit `45e3a564`; see [historical recovery](dev-record-lifecycle.md#milestone-records-and-historical-recovery).

### Task temporary material

Put task-specific temporary notes, sketches, probes, diagrams, review pages and logs under
`dev/tasks/<task-id>/.tmp/<purpose>/` in the canonical task folder on main, created only when needed.
Resolve session links before writing; if a session has no task link, use the canonical path directly.
Do not use the top-level `.tmp/` for task-specific work. Check that Git ignores the destination first.
When sessions contribute to the same task, use distinct purpose or session subfolders to avoid collisions.
Configured tool state, including pytest directories, Ruff caches and navigation shortcuts, keeps its
configured location and lifecycle.

Closing a persistent task retains its note and supporting evidence. Review disposable scratch separately;
closure grants no deletion authority and `--discard-scratch` is refused. Before explicitly authorized
cleanup, check containment, links and writers and preserve evidence needed by acceptance, landing or future
readers. Never delete another task's material. Evidence must survive until its consumer no longer needs it.
For work without a TODO item, keep transient notes in conversation; if files are necessary, use a
purpose-named folder under `dev/tasks/<purpose>/.tmp/` on main and clean it at completion.

**Three inspection helpers, all report-only by default** — `prune_series_cache.py` (orphaned WF2 series), `prune_climate_store.py` (stale `<source>_<window>` climate stores) and `snapshot_project_tree.py` (a tree as a path list, checked against the project-tree inventory; also `pixi run tree-check`). Deleting is an explicit owner action via `--delete`. Run pruning **before** any reference snapshot, or the snapshot bakes the orphans in and the gate compares those instead of the live artifacts. Neither prune tool sees everything: files under directories the path map routes wholesale need an mtime sweep.

The Quarto site stages ignored copies in `docs/site/guide/` during pre-render
and publishes them alongside `setup/`, `scientific-approach/`, and
`toolbox-reference/`. `notebooks/` holds source-only walkthroughs;

## .github/workflows/ci.yml

`pytest tests/` on ubuntu + windows with `locked: true`, so `pixi.lock` drift fails CI.

It covers only what a bare checkout can run. The fixture-dependent layer and the `--run-integration` tests skip, and `check_baseline.py` and whole-tree `semantic_tree_diff.py` cannot run there at all — they need the untracked `test_case/test_local` tree. **CI green does not mean the baseline was checked**; those stay local gates.

The baseline covers data, not figures. `FIGURE_KINDS` targets are excluded by default, since a figure is fingerprinted by byte size and any cosmetic edit would fail the gate without indicating a defect.

**A task that moves the project tree must grep the test suite for the old roots.** The fixture-dependent layer cannot fail in CI or in any worktree, so a stale path there survives every gate a branch can run — and a path behind an `os.path.exists` guard turns into a silent skip rather than a failure. Tree-shape gates (`semantic_tree_diff`, `check_baseline`) do not read the code that reads the tree, so they cannot substitute.

## Outputs

Outputs land under `project_dir`, set in the config. Production `project_dir` lives outside the repository tree; the untracked in-repo `test_case/test_local` is a dev/test exemption.

Execution diagnostics share `logs/<UTC timestamp>-<short invocation ID>/`: summary, console transcript,
workflow logs and Markdown/TSV benchmarks. Child invocations share their parent's folder; each retry
has fresh part namespaces. Historical shared logs and benchmark files remain untouched. The maintained
layout and interpretation live in `docs/guide/running.md` § Execution logs and benchmarks.
The WF2 product additionally owns `_engine/execution/` (production attribution and retained copies of
contributing logs) and, after an import, `_engine/imported/`; `docs/guide/outputs.md` owns both.

For new output projects, `config/<workflow>/` holds `run_record.yml`, captured files,
`SOURCES.md`, and `catalogs/` for the latest WF0–WF2
configuration archives. `SOURCES.md` lists the original source paths within each workflow folder.
Immutable generations live in `config/_engine/configuration-snapshots/<workflow>/<record-sha256>/`;
attempt history references those exact records, while unchanged captures reuse their creator generation.
Shared execution inputs, archive locks and invocation history live in `config/_engine/`.
Completed replacement backups and child launch contexts are transient. Existing cases can be inspected
or migrated with `scripts/maintain_config_archives.py` (`--apply` opts into changes).
There is no intermediate `config/runs/` directory. Editable source configurations
remain beside the project, outside these generated archives.

`experiments/_engine/{allocation.json,transactions/}` owns project-wide numbering and creation
recovery. Each `experiments/<name>/_engine/` owns that experiment's reservation, simulation and indicator
records. Discovery skips the reserved collection-level `_engine/` directory. These paths replace
`config/experiments/` for new projects; existing output trees are not migrated.

## Three homes for executables

The split itself is stated in `AGENTS.md` § Repo Map, which is what shipped modules cite by name.

`dev/scripts/` is not only executables. It also holds libraries `tests/` imports via `sys.path` — `semantic_tree_diff.py` (tree comparators and the project-tree inventory) and `cross_workflow_inputs.py` (stages the wf1 leaves WF2/WF3 need on disk), and `sweep_common.py` (the `Allowance`, walk and fail-closed `Floor` shared by the sweeps). A bare-checkout CI run imports both, so an import-time error there fails the suite on both legs. Treat them as contract surfaces with test consumers.

**One sweep, built on `sweep_common.py`.** `sweep_unread_config_keys.py` (`C-37`) asks *does this declared key reach a reader* — the templates a user copies on one side, the run-path surfaces on the other. It does not edit. It **fails closed**: an unclassified hit is a defect, and a check that can no longer see its own subject matter reports that instead of reporting a clean tree — R14's own re-measure returned zero and flagged MORE while knowing LESS, which is the shape it is built against. The R14 stale-spelling and identity-rename sweeps were retired with their campaign (t2610041227).

**When something in `dev/scripts/` acquires a run-path caller, move the shared part into the shipped package** rather than importing `dev/` from a run; a user's checkout is not guaranteed to have it. A list of paths that both a run and a fixture need belongs in `blueearth_cst/shared/`, while staging machinery only tests call stays in `dev/`.

**`dev/scripts/console.py` is vendored — do not edit it here.** It is a byte-identical copy of the `console-formatting` skill's module, consumed only by `stage_data.py` and `stage_cmip6.py`. Fix a console defect upstream and re-copy the file; a fix applied here is overwritten by the next re-vendor. `console.__version__` records the release the copy came from — compare it against that skill's `SKILL.md` frontmatter before changing either tool's console surface, and read a missing `__version__` as older than every version that has one. `[tool.ruff.format]` excludes it so a re-vendor diffs against upstream rather than against our own reformatting; `ruff check` still lints it.
