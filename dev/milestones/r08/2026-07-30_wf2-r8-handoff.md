## 5. Operational notes that cost time to learn

- **Iterate with `config/workflows/snake_config_dev_fast.yml`** — 2 series
  instead of 9, its own `project_dir`. Never point `check_baseline` at it.
- **Long runs: bounded foreground calls, not background.** Three background runs
  were killed mid-write this session; two left a manifest-pinned target
  half-written, one left the handle in §3. Drive remote reads one model per call —
  not because `ssp585` is slow (it is not, §4 item 3) but because a cold glob
  resolution can take 10–20 minutes for **any** source.
- **Put targets BEFORE the flags.** `--configfile` takes multiple values and will
  silently swallow a target path, then fail trying to YAML-parse a netCDF (`0x89`
  in the traceback is HDF5 magic).
- **`--rerun-incomplete`** is the recovery when a kill leaves a pinned target
  half-written.
- **`update()` on a persistent output is load-bearing.** Snakemake removes
  existing outputs before every job, so a revalidate-and-skip pattern silently
  never fires without it. Preserve it across any output rename.
- **Never reconstruct a model name from a wildcard.** `/` is sanitized to `_` and
  CMIP6 model names contain both `-` and `_`, so a sanitized name cannot be parsed
  back. Use a parse-time key→tuple lookup (`SERIES`, `POINT_KEYS`) with
  `wildcard_constraints`. This bug was hit twice, in two different rules.
- **A lazy multi-file read followed by a write is a deadlock candidate on
  win-64.** `open_mfdataset` + `xr.merge` + `to_netcdf` parks dask's thread pool
  on the HDF5 global lock. `.load()` after slicing is the established fix here;
  `DASK_SCHEDULER=synchronous` is the one-line probe that confirms it.
- **Use Write/Edit for content with escape sequences.** `\n` inside a quoted
  heredoc was mangled three times this session.
