Task Brief — `dev/scripts/build_sample_bundle.py`

### Context

Canonical ruleset: `AGENTS.md`. Read it first; this brief assumes it.

- **The input contract already exists** and is the single source of truth:
  `dev/scripts/sample_bundle.yml`. Do not add a second place to configure the
  sample. Every parameter the builder needs is there, and the cross-checks it
  must enforce are written as comments beside the keys they govern.
- **Why the bundle exists**: a user with no Deltares `P:` access and no cloud
  credentials must be able to run all four workflows. The promise is *no
  credentials and no `P:` drive*, not *no internet* — `pixi install`,
  `pixi run install` and juliaup all need the network. Scope against the real
  promise.
- **Two producers already do the hard parts.** `dev/scripts/stage_data.py`
  mirrors a bbox-clipped subset of the hydromt tree; `dev/scripts/stage_cmip6.py`
  writes digest-stamped CMIP6 slices that WF2 accepts as its own `raw/` cache.
  This builder ORCHESTRATES them from one recipe. It must not reimplement
  either, and must not add a second way to read a store.
- **Three homes, by invocation model** (AGENTS.md): this builder is
  maintainer-only and never part of a run, so it belongs in `dev/scripts/`.
  The fetcher a user runs belongs in `scripts/`, and is NOT this task.
- Sizing, measured 2026-08-19: **~93 MB** at the current recipe — era5 53 yr
  × 7 vars (28.7 MB), CHIRPS 41 yr (34.0 MB), static spatial (24.1 MB), 60
  CMIP6 slices (5.4 MB). Time range dominates cost; bbox does not.
- Full rationale and the evidence behind each constraint below:
  `dev/working/2026-08-19_shipped-sample-dataset/design.md`. Board item:
  `dev/tasks/t2608191733-ship-a-sample-dataset-bundle-so-a-user-needs-no-deltares-p-drive.md`.

### Goal

One script that turns `sample_bundle.yml` into a self-contained, reproducible
bundle directory plus a tracked checksum, such that a fresh checkout with that
bundle unpacked runs all four workflows with the network disabled.

### Non-goals

- `scripts/fetch_sample_data.py` — the user-facing downloader. Separate unit.
- GitHub Release creation or upload automation. The builder produces an archive
  and a checksum; publishing is a human step.
- Arbitrary user basins. The CMIP6 slices are fingerprinted on one polygon by
  design.
- A second sample basin, a baseline-scale variant, Docker packaging.
- Any change to how hydromt reads data or how Wflow parameterizes physics
  (AGENTS.md Hard Constraints). A genuine upstream bug is worked around in our
  own code, never patched in a vendored package.

### Allowed scope

**Permitted**

- `dev/scripts/build_sample_bundle.py` — new.
- `dev/scripts/README.md` — one table row, matching the existing entries.
- `tests/test_build_sample_bundle.py` — new.
- `dev/scripts/stage_cmip6.yml` — fix the stale `buffer_degrees` key, which
  `stage_cmip6.py` ignores (its `load_config` uses `setdefault` and rejects no
  unknown keys), so the line is inert and agrees only by coincidence of value.

**Approval-gated** — do not touch until the named gate is cleared

- `dev/scripts/stage_data.py` — only for the empty-clip behaviour, and only
  after **Gate 1** below. It is a shared producer with other callers.
- `test_case/snake_config_sample.yml` — the sample run config. Gate 2. It MUST
  keep the `snake_config_` prefix: `.gitignore` un-ignores `test_case/*` only
  through `!test_case/snake_config_*.yml`, so any other name is silently
  untracked. (A rename to `project_config_` is boarded separately; do not
  pre-empt it.)
- `.gitignore` — one entry for the unpack directory.

**Forbidden**

- `config/catalogs/cmip6_data.yml`, `config/catalogs/cmip6_store_index.json` —
  generated by `dev/scripts/generate_cmip6_catalog.py` from a live crawl. The
  builder COPIES them into the bundle; it never edits or regenerates them.
- `blueearth_cst/**` — the shipped package. This is a dev tool.
- `dev/scripts/console.py` — vendored byte-identical from the
  `console-formatting` skill. Fix defects upstream and re-vendor.

### Required changes (checklist)

1. **Read and validate the recipe.** Parse `sample_bundle.yml` and refuse, with
   a message naming the key, when any cross-check in its comments fails:
   historical span ≥ `constraints.min_historical_years` from
   `config/advanced_settings.yml`; `simulation` inside `historical`;
   `projections.historical_year_range` end ≤ 2014; `future_horizons.mid`
   CENTRED on `run.horizon`; `run.run_length` even; `buffer_cells` equal to
   `REGION_BUFFER_CELLS` in `analyze_projections.smk`; `climate.primary` and
   every `candidates` entry in `analyze_climate.smk`'s `_SUPPORTED_SOURCES`.
2. **Stage the spatial and meteo sources**, bbox-clipped, by driving
   `stage_data.py` from the recipe rather than from `stage_data.yml`.
3. **Write the bundle's own catalog**, `deltares_data_sample.yml`, with **no**
   `root:` and **no** `roots:`. hydromt then falls back to `dirname(yml)`
   (`data_catalog.py:from_yml`), so it can only ever resolve to the bundle, on
   any OS, wherever the user unpacked it. **Do not** add the sample root to the
   shipped `deltares_data.yml`'s `roots:` list — `_determine_catalog_root` takes
   the first path that `exists()`, so a user with the bundle would silently get
   this clipped Gabon-extent tree for their own basin.
4. **Delineate the region FROM THE BUNDLE, not from the source.** Call
   `blueearth_cst.spatial.delineate_region.delineate_region(model_region,
   data_libs=<the bundle's catalog>, hydrography=…, basin_index=…,
   region_out=…)` — it is a plain function, so this needs no Snakemake and no
   project. Passing the full `P:` catalog here is the subtle failure this step
   exists to prevent: a polygon delineated from unclipped hydrography can differ
   at the bbox edge from the one a user reproduces from the bundle, and every
   CMIP6 slice would then miss cache.
5. **Then stage the CMIP6 slices** with that polygon, via `stage_cmip6.py`.
   The order is forced — spatial → region → CMIP6 — because `region.geojson` is
   both an output of step 4 and an input to step 5.
6. **Pin the crawl products.** Copy `cmip6_data.yml` and
   `cmip6_store_index.json` into the bundle beside the slices. The index path is
   DERIVED, not configured: `analyze_projections.smk:312` sets
   `STORE_INDEX = Path(DATA_SOURCES).parent / "cmip6_store_index.json"`, so the
   file must carry exactly that name and sit beside the catalog, and pointing
   `project.data_sources_climate` at the bundle then picks both up.
7. **Emit the sample project config** (Gate 2), deriving every value from the
   recipe so the two cannot drift. It must set the waterbodies
   `timeseries_fn: null` — see constraint below.
8. **Write `BUNDLE.md`** into the bundle: provenance, per-source licence and
   `source_url` from the catalog metadata, the recipe's parameters, and what was
   deliberately cut.
9. **Write `sample_data.sha256`** into the REPO (tracked), not into the bundle.
   Release assets are mutable and deletable, so the repo holds the provenance.
10. **Make re-runs cheap and honest.** Re-running with an unchanged recipe must
    not re-stage; a changed recipe must re-stage only what changed, and must say
    what it skipped. Never silently truncate coverage (AGENTS.md: no silent caps).

### Gates

**Gate 1 — empty-clip fidelity.** `stage_data.py:791` returns `SKIPPED,
"no overlap"` and writes NO FILE when a vector clip has zero features. That
turns rule 1.08's `ok` (source readable, nothing in this basin) into `skipped`
(source absent) — a different provenance record for the same model, and `rgi`
on an equatorial basin is exactly that case.

Before changing anything: run one waterbody method against a valid but
zero-feature GeoPackage and observe whether `hydromt_wflow` returns cleanly or
raises `NoDataException`. **If it raises, `skipped` is honest and unavoidable —
do not write empty GeoPackages, and record that in the board item instead.**
Only if it returns cleanly does the empty-GPKG work have a purpose. Report the
observation before editing `stage_data.py`.

**Gate 2 — the sample project config.** Show the generated
`test_case/snake_config_sample.yml` for approval before committing it. It is a
tracked contract surface and the file a user copies.

### Acceptance criteria

Each property below names the observation that would disprove it and the command
that produces that observation.

1. **The bundle is sufficient.** Fresh checkout + unpacked bundle +
   `pixi run install`, then all four workflows on the sample config **with the
   network disabled**, run from the PRIMARY checkout (a slot worktree keeps its
   own `.snakemake`, so a run there is not the same run).
   *Falsifier*: any rule fails, or any log line shows a remote read.
2. **WF2 never touches the network.** *Falsifier*: rule 2.04's log lacks
   `raw cache_hit` for any series, or shows a fetch. *Command*: `grep -c
   "raw cache_hit" <project_dir>/logs/wf2_analyze_projections.log` equals the
   resolved series count (60 at the current recipe).
3. **The catalog resolves inside the bundle.** *Falsifier*: hydromt reports a
   root outside the unpack directory. *Command*: open the bundle catalog with
   `DataCatalog` and print its `root`.
4. **The polygon round-trips.** *Falsifier*: sha256 of the builder's
   `region.geojson` differs from the one a sample run writes to
   `<project_dir>/data/spatial/geoms/region.geojson`.
5. **Rule 1.08 reports honestly.** *Falsifier*: the sentinel at
   `<basin_dir>/staticgeoms/reservoirs_lakes_glaciers.txt` records a status that
   disagrees with Gate 1's finding.
6. **Re-running is a no-op.** *Falsifier*: an unchanged recipe re-stages
   anything. *Command*: run the builder twice; the second run reports zero
   bytes written.

### Output requirements

- A short summary naming what was staged, the bundle's total size, and every
  source that was skipped and why. Silence about a skipped source is a defect.
- Gate 1's observation reported before any `stage_data.py` edit.
- The generated sample config shown before it is committed.
- The board item's checklist updated in the same branch as the work.

### Task constraints

- **The offline promise is the acceptance test, not the design intent.** A
  bundle that looks complete and re-fetches one slice has failed.
- Do not hardcode data paths in a Snakefile or anywhere else; sources are named
  through a catalog (AGENTS.md Conventions).
- Python: `script:` modules read `snakemake.input/output/params` — this is not
  one of those; it is a CLI tool and takes `argparse`.
- Naming per `dev/reference/naming.md`; files kebab-case except importable
  Python modules, which are `snake_case.py`.
- Do not commit anything under `project_dir`, and do not hand-edit `pixi.lock`.
- Adding a dependency requires explicit owner approval before it is introduced.
