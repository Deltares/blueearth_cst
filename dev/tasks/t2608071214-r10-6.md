## Re-scoped 2026-08-19 — the gate PASSED on 2026-08-06; only scale is open

This note asked for a measurement that had already been made the day before it
was migrated off `dev/followups.md`. Its Detail section is the verbatim pre-board
prose, which is why it still says "asserted, not measured" — the ADR does not:

> **§8's acceptance gate is a measurement, not an assertion. PASSED 2026-08-06.**

Measured by `dev/decisions/0003-one-shared-region-artifact/probe_split_cost.py`
against the real `deltares_data.yml` catalog, timing the two halves exactly as
`prepare_spatial_products` calls them:

| | fixture config | `config_gabon0108.yml` |
|---|---|---|
| already paid today (`delineate_region`) | 5.58 s | 5.86 s |
| **§8 adds to WF2/WF3** | **3.65 s** | **3.89 s** |
| unsplit would add instead | 13.03 s | 13.17 s |
| **§8 avoids** | **9.37 s — 72.0%** | **9.28 s — 70.5%** |

`delineate_region` is excluded because WF2 and WF3 declare it under §1–7 either
way. Verdict recorded there: §8 is worth doing; the unsplit alternative is not.

**Why this becomes a watch-item rather than a closure.** The ADR's own caveat is
unresolved and cannot be resolved here: both configs resolve to the SAME 384-cell
basin, so which half scales worse is unmeasured. Checked 2026-08-19 — the only
real config on this machine, `C:/TESTS/CST/config_gabon1008.yml`, carries the
same `{'subbasin': [9.666, 0.4476], 'uparea': 100}` region at the same
resolution, so it is the same basin under a different name. The blocker the ADR
named ("no larger basin config exists on this machine") is still literally true,
which makes this a thing to watch for rather than work to schedule.
